fiscode is an estimator, not a filer. At year-end you hand off a yearly CSV (and the printable
year-end packet) to a tax pro, then import any amendments they send back.

## Export the year

From `/year-end`, click **Download &lt;year&gt; CSV**. You get:

- `fiscode-<year>-tax-year.csv` — every record dated within the year, plus the profile and the
  entity, spouse, and home-office spans that overlap the year. Rows you deleted in the app are
  left out, so the amounts in the file add up to what the app shows.
- A printable summary view (print the page to PDF).

The file opens in Excel, Google Sheets and Numbers as one small table per record type: income,
expenses, mileage and so on. Money is in dollars, dates are `YYYY-MM-DD`, and each code has a
label column beside it (`software_subs` next to `Software & subscriptions`). Ids and timestamps
sit in the last columns of each table. See [CSV format](/docs/csv-format) for every column.

If the accountant edits the file, ask them to keep dates as `YYYY-MM-DD`. A spreadsheet that
rewrites a date as `1/15/2026` makes the importer reject that row instead of guessing.

## Import an amended CSV

The yearly file is not a backup. It holds one year, and it leaves out deleted rows and archived
clients and vehicles. So the app does not let you **Restore** from it once the app holds data:
that would remove every other year. The dialog says how many rows would be lost.

What you can do with an amended yearly file today:

- **Rows the accountant added** (each needs an `id` that is not in the app yet): choose the file on the dashboard, then **Add rows**. Rows whose `id` is already in the app are skipped
  and the dialog counts them.
- **Rows the accountant changed**: make the same change in the app. Add rows never changes a row
  that is already there, so edits to existing rows in the file are not applied.

To move everything to another browser or machine, use **Download full CSV** and **Restore**, not
the yearly file.

Every import over existing data first records the state before it as one history entry.

## History & revert

Every write goes through a repository function that appends a `history` row with the before-state.
Revert is itself a non-destructive mutation — it writes a new row reflecting the revert and
appends another history entry.
